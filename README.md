# 「要吃啥子」小程序 · 部署与功能说明

> 微信原生小程序 + CloudBase 云开发（文档数据库 + 云函数）

## 一、项目简介

午饭决策助手。每天中午随机摇出 3 种餐别（共 5 张卡片：2 个常驻 + 3 个随机），点卡片看周边真实店铺，或选择「回家吃 / 点外卖」。选中某餐别后，次日不再推荐同款，避免连续两天吃一样的。

## 二、环境信息（已配置，供核对）

- **小程序 AppID** ：`你的小程序AppID`
- **云开发环境 ID** ：`你的云开发环境ID`
- **微信地图 Key** ：通过云函数环境变量 `MAP_KEY` 提供（生产推荐，避免硬编码泄露）。在云开发控制台 → 对应云函数「nearbyShops」→ 环境变量 设置 `MAP_KEY=你的腾讯地图Key`（WebServiceAPI 类型）。（Key 仅在服务端云函数内使用，不会进入前端包 / 代码仓库。）
- **代码入口** ：`miniprogram/app.js` 已 init 上述环境 ID。

## 四、云函数职责

- **dailyPick** 取/生成当天推荐。常驻项（home/takeout）永远显示；其余餐别随机取 3 个。查 `user_daily` 里"昨天"记录，把昨天选中的随机餐别从摇号池排除（实现"避免连续两天同款"）。`event.regenerate=true` 触发"换一批"，仅重摇随机部分，常驻项不动。
- **chooseMeal** 调用时记录当天 chosen（catId），供次日排除使用。
- **nearbyShops** 服务端用腾讯地图 WebService「地点搜索」，参数 `boundary=nearby(纬度,经度,半径)`。带 10 分钟 TTL 内存缓存（按地点+餐别+排序维度），避免反复点同卡片烧配额。支持 `sort` 参数：`'default'` 综合（腾讯原序）/ `'distance'` 按距离升序。home/takeout 项不调用此函数。
- **initCategories** 按 name 幂等写入餐别池，重跑只补新增、不动已有数据。
- **mealHistory** 按 openid 取最近 14 天 `user_daily` 记录，join 餐别名返回，供历史记录页展示（用了哪些卡片、当天吃了哪个）。

## 五、数据库集合（云开发控制台 → 数据库 → 新建）

- **meal_categories** 餐别池。字段：`{ name, emoji, mapKeyword, home?, takeout? }`
- **user_daily** 用户每日选择。字段：`{ openid, date(YYYY-MM-DD), picks:[catId...], chosen:catId|null }`
- 集合权限保持默认即可（所有读写经云函数管理员权限）。

## 六、部署步骤（重点！见下方"坑"）

1. 微信开发者工具导入项目：目录选仓库根，AppID 自动带出，后端服务务必选「微信云开发」。
2. 部署 5 个云函数（每个都要，见坑①）：文件树右键 `cloudfunctions/dailyPick` →「上传并部署：云端安装依赖」，同理对 `chooseMeal / nearbyShops / initCategories / mealHistory` 各做一次。（或右键文件夹选「上传并部署（全量上传 node_modules）」）
3. 建集合：云开发控制台 → 数据库 → 新建 `meal_categories`、`user_daily`。
4. 灌餐别池（可重复，幂等）：云函数列表点 `initCategories` →「云端测试」→ 事件参数留 `{}` → 运行。返回「已新增 N 个餐别」（首次 40，重复运行 0）。验证：数据库 `meal_categories` 应有 40 条记录。
5. 编译/上传前端：开发者工具「编译」看模拟器；上手机点「预览」重扫。

## 七、常见坑（务必看）

1. **云函数依赖丢失**（报错 `Cannot find module 'wx-server-sdk'`）：用「创建并部署所有文件 / 普通上传」只传代码、不装依赖。解决：右键函数选「上传并部署：云端安装依赖」（或「全量上传 node_modules」）。凡是改动过某个云函数代码再重传，都必须选这两项之一。
2. **上传报「请在云函数根目录选择一个云环境」**：`cloudfunctionRoot` 未绑定环境。本机 `project.private.config.json` 已写好绑定 `你的云开发环境ID`；若 IDE 仍报错，关闭项目重新导入根目录。
3. **地图报「boundary 不合法」**：该接口要求 `boundary=nearby(纬度,经度,半径)`，不用 `location/radius`。代码已修。
4. **地图报「KEY 每日调用量已达上限」**：WebServiceAPI 免费额度低。去 lbs.qq.com 做实名认证提额，或换新 Key 更新环境变量 `MAP_KEY`。`nearbyShops` 已带缓存，正常点几下不会烧光。
5. **真机查店失败 / 被拦截**：小程序后台「开发管理 → 开发设置 → 服务器域名 → request 合法域名」加 `https://apis.map.qq.com`。开发者工具勾"不校验域名"能跑，但真机必须配。
6. **模拟器无定位，查不到店**：开发者工具模拟器设「自定义位置」（如郑州 113.625, 34.746）再编译；或直接「真机调试」用手机 GPS，最稳。

## 九、玩法行为说明

- 每天首页固定 5 张：随机① · 随机② · 随机③ · 回家吃 · 点外卖（常驻 2 项固定在卡片最下方）。
- 「换一批」仅重摇 3 个随机餐别，常驻项不变（仍在最下方）；仍排除昨天选中的随机餐别。
- 选「回家吃 / 点外卖」→ 显示对应提示面板，不消耗地图配额，仍记录选择。
- 选随机餐别 → 显示周边店铺（名称/距离/地址），点店铺拉起地图导航。
- 店铺列表默认「综合」排序（腾讯原序），可点「距离最近」切换为按距离由近到远升序；距离显示已格式化（如 1.2km、>2km）。两种排序各有 10 分钟独立缓存。
- 首页右上角「📜 历史」可进入历史记录页，查看最近 14 天每天吃了啥、备选了啥。
- "避免连续两天同款"仅针对随机餐别，常驻项不受此规则影响。
- **趣味彩蛋（纯前端，云函数零改动）**：
  - 🔮 **今日运势**：顶部运势条每日一句「今日宜吃X，忌Y」+ 点评（按日期确定性随机，同天同结果）。
  - 📳 **摇一摇**：甩动手机即重摇（1.5s 防抖 + 震动反馈），右上角按钮可开关。
  - 🪙 **抛硬币定生死**：拿不定主意时点「抛硬币」，翻转后随机命中当前某张卡片并高亮。
  - 🎁 **盲盒模式**：点「盲盒」直接揭晓一个随机餐别（"命运让你吃这个"），可"就它了"或"再盲一次"。
  - 📤 **分享卡片**：点「分享」用 canvas 按当前主题配色生成战绩卡，可保存到相册发朋友圈。

## 十一、getLocation 接口权限申请模板（上传被拦「暂无权限」时用）

小程序用 `wx.getLocation`（精确定位），属受限接口。上传 `app.json` 时微信会校验该接口是否已在「接口设置」开通；未开通就报「暂无权限接口：wx.getLocation」。下方模板可直接照抄提交。

**入口**：微信公众平台 → 开发管理 → 接口设置 → 找「获取位置 / getLocation」→ 申请

**提交前自检**（不过这两关填得再好也易拒）：

- 服务类目含餐饮/外卖/本地生活/出行类（个人主体建议先去「设置 → 基本设置 → 服务类目」补一个，否则易被拒）
- 《用户隐私保护指引》已发布，且含「位置信息」项，用途描述与本模板一致
- 准备「首页 → 点选餐别 → 附近店铺（带距离）」截图

**接口使用场景说明（直接粘贴）**：

> 本小程序为午餐决策工具。用户在首页主动点选某一餐别后，小程序在用户点击操作下获取其当前精确位置（gcj02 坐标），调用腾讯地图 WebService 检索半径 2 公里内对应品类的餐厅门店，并按实际距离由近到远排序、支持一键导航到店。该场景依赖精确位置才能实现"就近就餐"与"距离排序/到店导航"，模糊位置无法满足门店级精度要求。位置信息仅在点选时获取一次，仅用于本次门店检索展示，不频繁获取、不另作他用，且仅向腾讯地图检索服务传输，不共享无关第三方。相关收集行为已在《用户隐私保护指引》中明示并取得用户同意。

**得分要点（审核看这些）**：

1. 用户主动触发——强调"点选卡片后"才获取，非后台静默/一进页就定位
2. 精确位置不可替代——明确"距离排序 + 到店导航"必须精确坐标
3. 低频 + 最小必要——"仅点选时一次""仅用于检索"
4. 与隐私指引一致——口径对齐

**被拒后**：看驳回理由。类目不符→换类目；场景不清→再强调"精确不可替代"；个人主体被拒基本无解，此时改走 `wx.getFuzzyLocation`（免申请，见下方附）或按城市搜索（云函数 `boundary=region(city,0)`）免权限。

**附：免申请替代方案**

不想走权限申请，可切换 `wx.getFuzzyLocation`（模糊定位，免接口申请、上传不拦，但精度下降、中心可能偏数百米~2km）。改动仅前端：`app.json` 的 `requiredPrivateInfos` 改 `["getFuzzyLocation"]`、`permission` 改 `scope.userFuzzyLocation`，`index.js` 的 `wx.getLocation` 改 `wx.getFuzzyLocation`；云函数字段名一致、零改动。注：两种方法都仍需发布《用户隐私保护指引》，真机才能授权调用。

## 十二、clone 后配置指引（协作者 / 换新机）

本项目已 push 到 GitHub（https://github.com/shixiaotuo/xcx）。clone 后无法直接跑，需补齐以下本地/云端配置（这些文件已被 `.gitignore` 忽略，不会进仓库）：

1. **导入项目**：微信开发者工具 → 导入项目 → 选仓库根目录。填你自己的小程序 AppID（仓库里 `app.json` 的 appid 为占位符，需替换）；或用测试号（功能受限）。
2. **绑定云环境**：顶部「云开发」→ 开通/选择环境，拿到环境 ID。把 `miniprogram/app.js` 里 `wx.cloud.init` 的 env 改成你的环境 ID。若开发者工具提示"请在云函数根目录选择云环境"，编辑 `project.private.config.json` 加：`"cloudfunctionRoot": { "cloudfunctions/": "<你的环境ID>" }`
3. **部署云函数（关键）**：分别右键 `cloudfunctions/` 下 5 个函数 →「上传并部署：云端安装依赖」（或「全量上传 node_modules」）。务必选带"安装依赖"，否则丢 `wx-server-sdk`。函数清单：dailyPick / chooseMeal / nearbyShops / initCategories / mealHistory
4. **配置 MAP_KEY 环境变量（周边搜必需）**：云开发控制台 → 云函数 nearbyShops → 环境变量 → 新增 `MAP_KEY=<你的腾讯位置服务 WebServiceAPI Key>`。⚠️ 仓库代码已去除硬编码 Key，仅靠此环境变量；未配会报"MAP_KEY 未配置"。申请地址：腾讯位置服务 console（lbs.qq.com）→ 创建应用 → WebServiceAPI Key。
5. **种入餐别池（首次）**：小程序内触发一次 dailyPick 会自动建当天记录；调 `initCategories` 云函数一键幂等写入 38 随机 + 2 常驻餐别（重复执行安全）。
6. **隐私与权限（发正式版前）**：「开发管理 → 接口设置」开通 getLocation（或改用 fuzzy 免申请，见十一章附）。「设置 → 服务内容声明 → 用户隐私保护指引」发布，含"位置信息"用途。
